## 一、开发目标

依据用户要求"同城业务提高为一级目录，层级太深了" + "推广到其他14个模块"，**按大厂业务领域导向重构菜单架构**，并推广 ershou 样板标准到其他14个垂直模块。

### 架构问题（当前5大中心架构）

1. "中台中心"概念混淆：pay/im/material/risk/ai 本质是模块，放中台中心造成分类混乱
2. "模块中心"成大杂烩：内容/同城业务/商家/营销/用户/社区全塞里面，层级深
3. 核心业务被埋：ershou/job/house 等15个垂直业务埋在模块中心下3级
4. 技术导向vs业务导向：5大中心是技术分层，大厂是业务领域分层

### 大厂参考

- 阿里/美团/京东/有赞：顶部Tab按**业务领域**组织（商品/订单/营销/数据/设置）
- 中台是后端概念，前端只有"设置"或"开放平台"入口暴露中台配置
- 核心业务直接一级Tab，不埋在二级菜单

- 数据库：15-20张表（主表+子表）
- 后端：60+ API（CRUD+交易+审核+统计+批量）
- 前端管理后台：15-16页面
- 前端C端：10-12页面+10组件
- 对标2-3个头部平台

**分批次推广**：
- 第1批（P1）：job / house / car（3个核心模块，对标招聘/房产/汽车头部平台）
- 第2批（P2）：love / pinche / linggong / dh114（4个特色模块）
